# 全息医学影像解剖台：运行、架构与替换指南

> 程序化演示 · 非临床使用。单张二维图像不能支持真实器官重建、病灶检测、毫米测量或心率测量。

## 1. 本次交付

在既有 React / Vite 质控工作台中增量增加独立暗色实验室，不替换原有米白／黄绿工作台。通过导航「全息解剖台」或 `/#hologram` 进入；返回按钮回到原工作台。

- 四类程序化器官：肺部、心脏、肝脏、大脑。默认肺部，器官由用户选择，不做自动识别。
- PNG/JPEG 选择、点击扫描仪上传、素材托盘拖拽投喂，以及系统文件放入场景。
- 六阶段流程、扫描音效、静音、跳过、旋转／缩放／平移、切片封口、预分块展开和演示异常发现。
- 已暴露异常可通过三维点击或侧栏按钮记录；发现后才显示其模拟尺寸、位置、置信度与说明。
- 完成后警示色与总结；重新扫描清空本次影像和发现，保留所选器官，并恢复静音。
- 文件树见 `FILE_TREE.txt`；所有项目源码与配置的逐文件完整内容见 `SOURCE_CONTENTS.md`。PNG 二进制素材和编译产物直接包含在交付压缩包中，不以伪代码代替。

## 2. 运行与验证

本轮实测环境：Windows 11、Node.js 26.7.0、npm 11.19.0、Chrome 154.0.8037.98。低版本 Node 和其他浏览器未做完整验收；单元测试使用 Node 原生 TypeScript 类型擦除。

在项目根目录执行：

```sh
npm ci
npm run dev -- --port 5173 --strictPort
```

打开 `http://127.0.0.1:5173/#hologram`。这是本机地址，不是公网部署。

常用命令：

```sh
npm run test       # 既有业务 + 全息模块单元测试
npm run typecheck  # 新 TS/TSX 模块与配置类型检查
npm run build      # 类型检查 + Vite 生产构建，输出 dist/
npm run test:e2e   # 自动启动或复用本机 5173 服务，使用已安装 Chrome
node scripts/audit-hologram.mjs
```

生产包预览：

```sh
node node_modules/vite/bin/vite.js preview --host 127.0.0.1 --port 5174 --strictPort
```

打开 `http://127.0.0.1:5174/#hologram`。`dist/` 必须经 HTTP 服务访问，不应双击 `index.html` 作为 file URL 打开。部署时请同时保留 worker 与所有 `assets/` 文件。

`playwright.config.ts` 默认 `channel: 'chrome'`，并为功能测试启用 SwiftShader，便于复现。可用 `PW_CHANNEL` 指定已安装的其他 Playwright 支持通道；本轮只验收了 Chrome。

审计脚本默认使用原生 GPU、1440×900 视口和内置合成影像。以下是 Bash / Git Bash 写法：

```sh
HL_BASE_URL=http://127.0.0.1:5174 node scripts/audit-hologram.mjs
HL_BASE_URL=http://127.0.0.1:5174 HL_RENDERER=software node scripts/audit-hologram.mjs
```

结果以独立时间戳目录写入 `artifacts/hologram/audit/`，含 JSON、各状态截图和视口检查。默认运行命令不需要任何 API key、远程模型或外部 GLB。

## 3. 最短演示路径

1. 点击「载入演示影像」；出现缩略图后，拖入扫描仪口径，或点击「开始扫描」。
2. 观看吸入、扫描、全息生成；也可点击「跳过动画」，只快进到观察阶段，不产生发现。
3. 拖拽旋转、滚轮缩放、右键／双指平移；「重置视角」恢复默认相机。
4. 悬停模型或选择部位索引；点击「进入解剖模式」。
5. 调整切片，使切面经过演示异常；或把展开滑块拉到 55% 以上。
6. 点击可见发光区域，或使用侧栏「可见演示异常」按钮。全部记录后显示完成状态。
7. 点击「重新扫描」重新开始。为确认切片规则，可将深度拉至 100%：已被切除的异常不会因为展开而被错误视为可发现。

移动端以粗指针默认选择轻量质量档；侧栏位于场景下方，可折叠。减弱动态模式会压缩阶段时长，停止晃动、持续转动与粒子脉动，保留可操作流程。

## 4. 数据与医学边界

### 实算内容

`decodeImage.ts` 读取文件头、校验类型与尺寸，使用浏览器解码。分析图像最长边不超过 256 像素；Canvas 读取亮度，Worker 计算直方图、对比度、边缘强度、点云及 relief 数组。Worker 不可用时，回退到有界的小图同步分析。

复现种子是文件字节的确定性非加密 hash。同一文件与器官会得到同样的演示映射；重新编码同一视觉内容或改变文件元数据可能改变种子。种子不是医学指纹，也不能用于身份识别或安全用途。

### 演示内容

器官曲面、组织分块、1–3 处异常、毫米尺寸、置信度、节律读数与说明均是程序化演示。像素统计仅驱动造型扰动和分布，不构成任何诊断或测量。

### 隐私及输入限制

- 上传在当前浏览器内存中处理，不向服务器上传，也不写入报告、质控、整改或浏览器存储。
- 默认静音；仅用户主动开启声音时创建 AudioContext。
- 单文件最大 20 MiB；宽高各不超过 8192，总像素不超过 16,777,216。浏览器还须能正确解码该 PNG/JPEG。
- 不接受伪装成 PNG/JPEG 的 SVG 或无效文件；不因点击跳过而绕过验证。
- 本地纹理最长边 256 像素，避免把原始大图长期保留在显存中。
- 内置 `src/assets/demo-chest.png` 是合成样例，不是患者病例。
- 请自行确认输入已脱敏且获授权；本地处理并不等于自动完成脱敏。

## 5. 架构与职责

```text
App.jsx（独立入口／lazy load，不改领域规则）
  └─ HologramLab.tsx（任务、资产与错误边界）
      ├─ state/labMachine.ts       离散状态、runId、发现门控
      ├─ hooks/useScanTimeline.ts GSAP 生命周期与快进
      ├─ hooks/useScanAudio.ts    用户授权音频与清理
      ├─ imaging/                解码、校验、Worker、确定性映射
      ├─ ui/                     HUD、投喂、信息／发现面板
      └─ scene/LabScene.tsx       R3F Canvas、相机、质量监测
          ├─ ScannerRig          扫描仪、纹理吸入、青色冲击波
          ├─ ProjectionStage     底座、网格、扫描幕、DNA、白环
          ├─ ParticleSystems     GPU 点云和火花
          ├─ OrganAssembly       器官、切片封口、展开、标签
          ├─ LesionField         演示异常、裂纹线框、粒子与拾取
          └─ PostFX              Bloom、色差、暗角、胶片噪声
```

关键约定：

- reducer 只管理离散状态；GSAP 只拥有时间包络；R3F 帧循环更新 transforms / uniforms，不用 React 逐帧重建整个 UI。
- `runId` 变更后，旧扫描回调无法推进新任务；发现必须处于 Stage 5、已暴露、ID 合法且未重复。
- shader 的切片／生成裁切同时约束射线拾取，避免点击被 shader 隐藏的部分。解剖状态下透明器官不截断通向内部异常的点击。
- 三维后处理只处理 Canvas；HUD、输入、侧栏文字不参与模糊、色差或视角震动。
- 资源各有所有者：资产释放 URL，解码关闭 ImageBitmap，Worker 结束或取消即 terminate，模型／材质销毁 dispose，时间轴 kill，音频 close。
- reset 保留可复用的扫描仪／底座，释放本轮图像与器官资源。GPU 内存回归对比需先预热；首次显示的常驻隐藏网格会延迟上传，冷启动计数不能直接当作泄漏基线。
- WebGL 丢失切换为明确标注的二维信息模式；仍能查看本地图像统计。返回工作台再进入可重新创建 Canvas，不伪装为三维仍在运行。
- `hologram.css` 独立 `hl-*` 作用域，Tailwind 仅引入带 prefix 的 theme / utilities，不引入 Preflight。

## 6. 各 Stage 动效参数表

以影像校验和本地分析完成、开始投喂为 t=0。解码耗时不包含在 5.45 秒表演时间内；隐藏标签页暂停，慢设备可能有调度偏差。主要时间参数集中于 `motion.config.ts`。

| Stage | 时间范围 / 时长 | 实现与默认参数 |
|---|---|---|
| 0 待机 | 不限时 | 扫描仪悬浮幅度 ±0.025U，周期 3.6s；内环周期 18s；微弱网格 |
| 1 投喂 | 0–0.65s / 0.65s | `power3.in` 吸入；透视倾斜与非均匀缩放；幽灵缩略图和尾迹；青色波环在投喂进度 35% 后展开并淡出 |
| 2 预扫描 | 0.65–1.35s / 0.70s | 连续强度包络从 0 升至 0.16；simplex 输入频率 6；x 位移上界约 0.012U |
| 2 峰值 | 1.35–3.05s / 1.70s | 强度升至 1 后回落至 0.4；频率 22；x 位移上界 0.075U，y/z 按 0.6 / 0.37 缩放；旋转上界 3.5° |
| 2 收敛 | 3.05–3.85s / 0.80s | 频率 9；强度以三次衰减收敛至 0；完整扫描阶段共 3.2s |
| 3 全息生成 | 3.85–5.45s / 1.60s | `reveal` 线性从底部扫向顶部；Fresnel、扫描线、噪点、线框与内部管路 |
| 3 白色环 | 3.85s 起 / 0.45s | `expo.out` 扩散，与生成重叠；不是全屏白闪；声音开启时短促定格音 |
| 4 空间观察 | 用户控制 | OrbitControls 阻尼 0.08；部位高亮时间尺度 0.15s；旋转、滚轮缩放、右键／双指平移 |
| 5 切片与展开 | 用户控制 | 切片 shader 平滑 0.12s；展开 0.70s `power3.inOut`；近凸分块交线封口 |
| 5 发现完成 | 0.60s | `power2.inOut` 向品红警示色过渡；侧栏显示发现总结 |
| 重新扫描 | 0.45s | `power2.inOut` 收回生成包络，清理本轮资源并回 Stage 0 |
| 减弱动态 | 每段 0.08s | 投喂／扫描／生成总计 0.24s；取消非必要持续动画，不自动发现异常 |

世界尺度 U 为 Three.js 演示场景单位，不是毫米，也不与实际患者器官尺寸对应。视角震动上界 0.009U，仅扫描期间使用。低频合成声音由 48Hz 向 82Hz 变化，最大增益 0.035；无外部音频资源。

质量档位集中于 `quality.config.ts`：

| 档位 | DPR 上限 | 粒子数 | 球面细分 | 后处理 |
|---|---:|---:|---:|---|
| high | 2 | 18,000 | 40 | Bloom、色差、暗角、Noise 0.018 |
| balanced | 1.5 | 8,000 | 28 | 较低 Bloom 分辨率、色差、暗角、Noise 0.012 |
| low | 1 | 2,500 | 18 | 关闭 EffectComposer；保留材质与界面层次 |

DPR 是上限，实际不强制把 DPR=1 的显示设备渲染成 2 倍。预热超过 3 秒后，连续 3 个采样窗低于 45 FPS 会下降一档；不自动反复升降。粗指针设备默认 low。帧率是短时实际观测，不代表任意硬件均能达到 60 FPS。

## 7. 用真实模型替换占位器官

唯一模型适配入口为 `hooks/useOrganModel.ts` 中的 `useOrganModel(type, quality, analysis)`；后两个参数有默认／可选值，保留 `useOrganModel(type)` 调用方式。

1. 将授权模型放在自托管资源目录，按器官／LOD 分别加载；不要把所有大型模型打进主工作台首屏。
2. 在适配层使用 GLTF / 其他加载器，输出当前 `{ name, english, description, parts }` 结构。每个 part 保留稳定 `id`、`name`、`position`、`explodeDirection` 和 `BufferGeometry`。
3. 将子网格变换烘焙到自己拥有的几何副本中，统一至器官本地坐标：底部约 y=0、顶部不超过约 2.4，中心轴接近 x=z=0。不要对缓存共享 geometry 随意 dispose。
4. 保留帧循环与 shader 合同：`uReveal`、`uClip`、`uHover`、`uWarning`。若改尺度，同步修改切片面、射线过滤、病灶映射与相机距离。
5. 当前 `createSliceCap()` 使用交点凸包，仅适用于近凸程序化分块。真实非凸、带孔或多连通模型需要 stencil caps、可靠的剖切网格算法或分割体渲染；不能直接宣称现有封口适用于临床模型。
6. 演示异常不得冒充模型中的真实病灶。真实标注必须来自经过验证的分割／标注数据，并保留出处与坐标映射。应先通过独立医学与软件验证，再讨论临床用途。
7. 增加模型加载错误与取消处理，维持 runId 隔离、有限资源预算与卸载释放。

## 8. DICOM 接入说明

本次全息模块只接收 PNG/JPEG。项目原有 `src/dicom.js`、`src/DicomViewer.jsx` 保留原职责；已有读取器仅能作为有限未压缩单帧灰度 CT 支持的参考，不是通用 PACS 或三维重建引擎。

真正的 DICOM 路径至少需要：

1. 获授权且完成脱敏的序列输入；校验 Study / Series、Modality、SOP、Transfer Syntax、帧数与像素格式。
2. 使用支持对应传输语法的解码器处理压缩／多帧数据；不要通过放宽扩展名检查绕过解码能力。
3. 根据 ImageOrientationPatient、ImagePositionPatient、PixelSpacing 和实际层间距离建立患者坐标仿射；处理缺层、重复、斜切与不均匀间距。
4. 正确处理 Rescale Slope / Intercept、MONOCHROME1/2、窗宽窗位、方向与单位。不能仅按文件名或 Instance Number 盲目拼体。
5. 组装体素体并在 Worker / 合适的计算后端完成分割或等值面；提供加载取消、分块传输、内存上限与错误恢复。
6. 在 `useOrganModel` 适配真实分割网格，或另建 volume renderer；将病灶与患者坐标、分割掩码、版本和来源绑定。
7. 用已知 spacing / orientation 的参考数据验证几何与测量误差，经过医学、隐私与监管审查后才可支持临床声明。

若只是演示现有 DICOM 的二维内容，可先经已授权工具脱敏、窗宽窗位渲染后导出 PNG/JPEG 再投喂；此操作仍然不构成真实三维重建。
